# PMMS

**PETRONAS
Maintenance
Management
System**

PETRONAS Maintenance Management System (PMMS) is the PETRONAS Groupwide software supported system to manage physical assets at Operating PETRONAS Units (OPUs). Currently the system is based on SAP Enterprise Resource Planning (ERP) and in particular the Plant Maintenance (PM) module. Functionalities in PMMS are designed / adapted to extensively support the predefined maintenance management work processes. Key success factors are consistent application of the functionalities, and accurate and meaningful data entered, processed, maintained and utilized for analysis & improvement.

Key objectives of PMMS are:

- Provision of comprehensive Asset Equipment Data, Planned Preventive Maintenance (PPM) programme, and Work Process Management, for effective maintenance work process implementation and continuous improvement.
- As single repository for maintenance data; to capture all static & dynamic data particularly maintenance work / relevant historical data, for asset & cost analysis and continuous improvement.
- Assurance of Asset Integrity with comprehensive ITPM, PPM roll out, analysis and continuous improvement.

### Physical Asset Management (PAM)

Under OEMS2.0, Physical Asset Management is a process through which the high value decision regarding use and care of assets are planned and executed.

- Maintenance Strategy

**Maintenance Plan** is a description of the preventive maintenance and inspection tasks to be performed at the equipment concerned at predefined intervals.

**Maintenance Strategy** is a function in SAP that contains scheduling elements for Maintenance Plan (e.g. scheduling parameters and maintenance packages)

**Task list** is a function in PMMS for maintenance engineers or planners to define clear, concise instructions and work steps to help a technician to carry out work efficiently.

**BOM** - A list of all the parts and components that make up a particular asset.

**Functional location** represents the location of a technical system at which maintenance can be performed. It can represent a plant area/ module, a system (e.g. turbine system) or down to the tag number level

**Equipment** is an individual object that represents a maintainable item (e.g. Centrifugal Pump) that can be installed to a Functional Location

**Catalogue Profile** - a combination of standardized codes that are used for failure analysis. It consists of symptom, object part, damage and cause codes used during technical reporting.

# MAINTENANCE STRATEGY, PLAN & TASK LIST

The tasklist is a work instructions, where the detailed tasks are stored as a Standard Text created from the tasks generated from Job library or Reliability studies e.g. ERS/ITPM.

Each active equipment is to be assigned with active Maintenance Plan (or Mplan) or Run to Fail (RTOF).

## BOM

**Objectives of BOM :**

i. To improve planning efficiency ( spare parts ) of maintenance
ii. To ensure correct parts with the right specifications are used hence reducing error in purchasing equipment parts.
iii. As reference for complete list of equipment component breakdown.

BOM shall be assigned at the lowest level of the Maintenance Asset Structure hierarchy. It can be created as single or multilevel BOM.

**Basic flow of BOM creation**

BOM Assembly → BOM

**Priority for the creation of BOMs are as follows:**

1. Equipment identified as Safety Critical Elements (SCE) (highest priority)
2. Equipment identified as C1 criticality
3. Equipment identified as C2 criticality
4. For equipment identified as C3 criticality, it is recommended that BOM is created to help the user to purchase material

Each equipment will be assigned with BOM or NBOM status ( not require BOM ). Example of NBOM equipment are structures, piping, stack/vent, escape route.

## PMMS WORK MANAGEMENT EXECUTION

PMMS Work Management Execution (PWME) is an integrated process of day-to-day Maintenance Work Management from Work Identification to Closing and Analyze. It is an integral part of OEMS-Physical Asset Management (PAM) under Work Planning & Scheduling element (WPS).

The main objective of PWME is to achieve effective Maintenance Work Management via:

- Appropriate identification and prioritization of work
- Systematic work preparation for both preventive and corrective maintenance
- Build rolling Schedule of Work (7 days schedule with seamless link to 90/30 days plan and higher level 1+4 years & Asset Specific Maintenance Reference Plan)
- Systematic management work planning and scheduling including break in jobs
- Execute the work to a high standard of safety and quality
- Perform continuous analysis and improvement based on timely and accurate recorded data

# 1.0 WORK IDENTIFICATION

A Notification ( Work Request ) is to be created when equipment is found unable to perform the expected function, or has indication of failure, and after site troubleshooting, the equipment is still unable to return to expected functional level, and/or require further maintenance address. If the issue is resolved 'in-situ', it is recommended to raise Notification and proceed with closure (NOCO) for record purposes.

Notifications may be raised by anyone authorised; typically, by Operation, the Inspection group or Maintenance Team.

Before raising notification, following information need to be prepared:

- Tag ID number or Equipment number
- Functional Location (FLOC) - mandatory
- Initial prioritisation using standard Risk Assessment Matrix (RAM)
- Required End Date
- Detailed observation of the defect
- Mitigation / temporary repair performed, if any
- Shutdown / Isolation requirement
- Whether it is a breakdown
- Date and Time that the defect began or when it was first detected
